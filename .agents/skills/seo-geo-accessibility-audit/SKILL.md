# seo-geo-accessibility-audit

Lire ../../../SEO_GEO_ACCESSIBILITY.md et les trois règles détaillées liées. Lire todo.md en entier et tasks.md pour connaître les décisions, travaux précédents et actions externes.

1. Inventorier routes, langues publiées, gabarits, ressources Forge, formulaires, réservation, menus et modales. Relever les limites d'accès et l'état du dépôt sans afficher de secrets.
2. Contrôler SEO technique et éditorial, navigation et sémantique, accessibilité visuelle/clavier/lecteur d'écran selon les outils disponibles, contenu citable et politiques de robots IA. Inspecter les métadonnées de toutes les routes lorsque possible ; documenter les échantillons manuels par gabarit/langue et les états couverts. Vérifier les sources officielles pour les politiques moteur changeantes.
3. Utiliser les contrôles existants pertinents. Un build peut produire ses artefacts locaux ; ne pas installer de dépendance ni modifier le code pour faire passer l'audit. Ne pas soumettre un formulaire réel ni déclencher de publication. Une panne Forge ou un outil absent doit figurer dans les limites.
4. Mettre à jour uniquement les deux sections SGA de todo.md selon le format commun. Conserver les sections existantes et dédupliquer avec leurs tâches. Dans la section propriétaire, demander uniquement les faits, accès ou actions réellement manquants ; une information déjà confirmée n'est pas à redemander sans contradiction nouvelle.
5. Rapporter les principaux problèmes, leur impact, le nombre de tâches ajoutées/actualisées et ce qui reste non vérifié. L'audit n'est pas une correction ni une certification.
